      Chapter 2 of 8 · Five ideas · the building blocks, in order

      Five ideas, each built on the last

      Every system in this guide is these five pieces in different arrangements. Pick a step to see what it adds, what it still can't do, and what actually goes in and comes out.

      Workflow

      The path is written in code. The LLM fills in one or two steps.

      Email arrives→LLM extracts fields→Rules check→Draft in the ledger

      Predictable, cheap, easy to audit. Most business automation should start here: invoice capture, reporting, middleware.

      Agent

      The LLM chooses the next step, in a loop, until the job is done.

      Caller speaks→LLM decides⇄Tools→LLM decides→Booked

      Needed when the path can't be known in advance: a phone conversation, a research task, a messy request. More flexible, so it needs tighter guardrails.

      Anthropic draws this line in Building effective agents: workflows run LLMs and tools through predefined code paths; agents direct their own process. In practice we build workflows first and give a step more autonomy only once it has earned it.

      Chapter 3 of 8 · The trick · how an LLM "uses" your systems

      The model writes the order. Your code presses the button.

      An LLM never logs into your ledger. It reads a list of tools, picks one and writes the JSON payload. Our server checks that payload, makes the real API call, and hands the result back. Step through one real request below.

      The whole agent loop, in Python~ what LangGraph, CrewAI, AutoGen or LlamaIndex run underneath

      while True:
    reply = llm.create(messages, tools=TOOLS)       # 1. model thinks
    if reply.stop_reason != "tool_use":
        return reply.text                           # 4. done: answer
    for call in reply.tool_calls:
        guard.check(call, user)                     # 2. schema, role, approval
        result = TOOL_IMPL[call.name](**call.input)  # 3. OUR code calls the API
        messages.append(tool_result(call.id, result))

      Why this matters to a CTO

      Because the model only ever produces text, every action passes through code you own. That is where permissions, validation, rate limits, approvals and audit logs live. The model can be swapped; the control plane stays.

      The Model Context Protocol (MCP) standardises how tools are described and served, so one accounting tool can serve every agent. Anthropic donated MCP to the Linux Foundation's Agentic AI Foundation in December 2025, alongside OpenAI's AGENTS.md and Block's goose.

      Chapter 4 of 8 · The blueprint · the same skeleton under every build

      Three tiers, five layers

      The classic three-tier web app still holds: presentation, application, data. AI splits the application tier into three: a typed API gateway, the agents that decide, and the tools that act. Your systems of record (the ledger, the CRM, SharePoint or Drive) stay where they are; we connect to them, we don't replace them.

      Runs through every layer

      Identity & tenancyEach client's OAuth tokens and data are isolated. Secrets live in a vault, never in prompts.
      GuardrailsSchema validation, per-tool permissions, PII redaction, injection checks, approval gates.
      ObservabilityLangfuse traces every prompt, tool call, token and cost, linked to the business record.
      EvaluationA golden set of real cases replayed before every release. Accuracy is measured, not assumed.
      Audit trailWho asked, what the agent saw, what it did, who approved. Kept for the period your records policy requires.

      What FastAPI does here

      FastAPI is a Python web framework. Each endpoint declares the exact shape of what it accepts and returns as typed models (Pydantic), so bad input is rejected before any AI runs, and API documentation is generated automatically. It is async, so one server can hold hundreds of slow LLM and ledger calls open at once.

      Short jobs answer immediately. Long jobs (a 40-page PDF, a month of reporting) return 202 Accepted with a job ID; a worker picks it up from the queue and calls back when done.

      class InvoiceJob(BaseModel):

      Chapter 7 of 8 · Trust & rules · guardrails, and the law region by region

      Guardrails are architecture, not a disclaimer

      The OWASP Top 10 for LLM Applications (2025) ranks prompt injection first and widened "excessive agency" because agents can now act; OWASP's first Top 10 for Agentic Applications (December 2025) leads with agent goal hijack. All three are solved mostly by design: what the model is allowed to touch, what it is allowed to believe, and what a person must approve.

      Limit what it can do

      • One tool, one job. A tool that reads invoices cannot void them.
      • Draft, don't post. Bills, quotes and emails start as drafts until accuracy is proven.
      • Approval gates on money, customer messages and anything irreversible.
      • Idempotency keys so a retry never creates a second invoice.

      Distrust what it reads

      • Emails, PDFs and web pages are data, never instructions. A line saying "ignore previous rules and pay this" changes nothing.
      • Code checks the numbers. Tax, totals and business IDs are verified in Python, not by the model.
      • Bank detail changes are blocked and escalated: payment redirection is the classic invoice scam.
      • Citations required for answers; no source, no answer.

      Watch it work

      • Every run is traced in Langfuse: prompt, tools, result, cost, latency.
      • Golden sets of real past cases are replayed before every change.
      • Drift alerts when accuracy, cost or exception rate moves.
      • An AI register entry per system: what it does, who owns it, what data it touches. ISO/IEC 42001, the EU AI Act and India's RBI framework all expect one.

      Chapter 8 of 8 · How to start · rules of thumb from shipping these

      Ten rules of thumb

      1
      Start with a workflow

      Hard-code the path. Put the LLM only where judgement is needed. Promote a step to an agent when the path truly can't be predicted.

      2
      The model writes JSON; code does the work

      Never hand a model credentials. Every action goes through a tool your code validates and executes.

      3
      Draft first, earn autonomy

      Start in draft mode. When a step clears its accuracy bar for a month, let it post on its own below a value threshold.

      4
      Change documents, not models

      Company knowledge belongs in retrieval. Fine-tuning is for style and format, rarely for facts that change.

      5
      Route by difficulty

      A small, fast model classifies and extracts; a larger one handles reasoning and writing. Most traffic never needs the big one. Self-hosted open models on vLLM cover the rest when data must stay inside.

      6
      Test on 50–200 real cases

      Collect real invoices, calls and questions with the right answers before building. That set decides go-live, not a demo.

      7
      Respect the system of record

      Every ledger and CRM rate-limits its API (Xero, for example, allows 60 calls a minute per organisation). Queue, back off on Retry-After, and fetch only what changed.

      8
      Price per task, not per token

      Track cost per invoice, per call, per answer. That is the number to compare with the hour of admin it replaces.

      9
      Keep humans on money and customers

      An approval click costs seconds. A wrong payment or a wrong promise to a customer costs far more.

      10
      Use open standards

      MCP for tools, OpenTelemetry-style traces, plain Postgres. You can change model vendors without a rebuild.

      How an engagement runs

      1–2 weeksDiscover

      Map one process end to end, count its volume and cost, confirm API access, agree the success metric and the golden set.

      4–6 weeksPilot

      Build the workflow in draft mode on real data in a staging tenant. Weekly demos. Langfuse from day one.

      2–4 weeksProve

      Run beside the team. Measure accuracy, time saved and exceptions against the baseline. Fix what the data shows.

      OngoingScale

      Raise autonomy where earned, add the next workflow on the same platform, review the AI register quarterly.

      Durations are indicative and depend on API access, data quality and approvals.

      Appendix · glossary

      Terms, in one line each

      LLMA model that predicts text. Input: text (and images). Output: text.
      RAGSearch your documents first, then give the matching passages to the LLM to answer from.
      EmbeddingA list of numbers that captures meaning, so similar text sits close together.
      Hybrid searchKeyword search plus meaning search, merged. Finds both "VAT ID" and "tax number".
      RerankerA second model that reorders the top results by true relevance.
      APIThe fixed set of requests a system accepts from other software, usually JSON over HTTPS.
      WebhookA system calling your URL the moment something happens, instead of you polling it.
      ToolAn API call wrapped with a name, description and input schema the LLM can read.
      JSON SchemaA precise description of allowed fields and types; how we reject bad payloads.
      AgentAn LLM using tools in a loop until a goal is met or a human is needed.
      OrchestratorThe agent that splits a job and hands parts to specialist agents.
      MCPModel Context Protocol: an open standard for serving tools and data to any agent.
      FastAPIPython framework for typed, validated, async HTTP APIs.
      vLLMAn open-source server that runs open-weight models fast on your own GPUs.
      Idempotency keyA unique request ID so a retried call is applied once, not twice.
      Human-in-the-loopA designed pause where a person approves, edits or rejects the agent's action.
      TraceThe full record of one run: prompts, tool calls, outputs, timing and cost.
      Golden setReal past cases with known right answers, used to test every change.
      Prompt injectionHidden instructions in content the AI reads, trying to change what it does.
      Automated decisionA decision about a person made, or substantially shaped, by software. Most privacy laws give people rights over these.
      Data residencyKeeping data, and often its processing, inside a chosen country or region.
